# 破冰协议 · 战略定位与竞品对标分析

> 日期：2026-05-25
> 来源：基于 Thawly.ai 等新兴竞品的深度对标分析

---

## 一、差异化定位声明

### 一句话版本

> **Thawly.ai 是陪你散步的拐杖，破冰协议是逼你交稿的契约。**

### 对比矩阵

| 维度 | Thawly.ai | 破冰协议 |
|---|---|---|
| **核心假设** | 你动不了，需要外部推力 | 你怕做不好，需要心理许可 |
| **目标用户** | ADHD / 任务瘫痪 / 执行功能障碍 | 完美主义者 / 高思考低行动 |
| **交互模式** | 陪伴式（Continuous Execution） | 契约式（启动契约 + 限时交付） |
| **时间粒度** | 2 分钟微行动 | 15 分钟步骤（含三阶段计时） |
| **交付物** | 无明确产出，重在"做了" | 可导出的 Markdown 雏形 |
| **迭代哲学** | 持续陪伴，不离开 | 只改一处，防止完美主义无限循环 |
| **情绪干预** | Coach Mode 引导提问 | "乱写模式"强制降低标准 |

### 为什么这个差异很重要

Thawly.ai 的用户（ADHD）需要的是**外部结构**——他们内在缺乏组织感。破冰协议的用户（完美主义者）内在结构过剩（永远在脑子里规划），缺的是**对外交付的许可**。

你不是要"陪"他们，是要**逼**他们跨过心里那道线。

### 定位声明（用于对外传播）

> 市面上教你"如何规划""如何坚持"的工具已经够多了。完美主义者不缺规划——他们缺的是从"想"到"做"的那一瞬间的操作指令。破冰协议不管理任务、不切割时间、不提供激励。它只做一件事：**把启动成本降到零，并逼你交出一个可改的雏形。**

## 二、对标优化：逐步执行功能

### 2.1 破冰协议已有优势（代码已实现）

| 功能 | 代码位置 | 说明 |
|------|---------|------|
| 三阶段计时器 | `demo/index.html:2420-2491` | `draft`（乱写期）→ `refine`（修整期）→ `panic`（紧急期） |
| 无活动监控 | `demo/index.html:2500-2558` | 60 秒无输入自动打开帮助抽屉并主动介入 |
| 主动提议 | `demo/index.html:2379-2418` | 基于前序产出给开场建议 |
| 提示词起搏器 | `demo/index.html:3000-3056` | 根据步骤内容智能推荐追问 |
| 语音输入 | `demo/index.html:3320-3630` | 三个位置（Landing/Help/Workspace）的语音识别 |
| 附件解析 | `demo/index.html:1856-1994` | 支持 PDF/DOCX/XLSX 后端解析带入 AI 上下文 |

### 2.2 可借鉴 Thawly.ai 的优化方向

#### 优化 1：步骤内微行动分解（最高优先级）

当前每步 15 分钟对重度完美主义者还是太长。建议在 `goToStep()` 开始时，AI 再把这一步拆成 3-5 个**微勾选项**：

```
步骤：写博客大纲（15分钟）
  ☐ 先写第一个小标题（不管好坏）
  ☐ 再写第二个
  ☐ 填一个具体例子
  ☐ 加个结尾句
```

每勾选一个，进度条前进一小格。这比"盯着空白文本区 15 分钟"压力小得多。

**实现思路**：在 `renderStepInstruction()` 中增加微行动列表，用 checkbox 状态驱动局部进度。

#### 优化 2：自动过渡，减少"点击下一步"的决策点

当前必须用户主动点"做完了，下一步"。可以在 `finishStep()` 前增加**智能检测**：

```javascript
// 如果用户已经写了超过100字且计时器还剩5分钟以上
// 弹出轻量确认："看起来你已经完成了，进入下一步？"
// 用户按空格或回车即可确认，不需要鼠标移动
```

#### 优化 3：步骤间 AI 过渡语

当前完成一步后直接进下一步，缺少 Thawly.ai 那种"有人在你身边"的连续感。可以在步骤切换时插入 AI 总结/鼓励：

> "第 1 步完成。你现在已经有了核心观点——比 90% 的人强了。接下来我们把它变成大纲，不需要想得太复杂。"

#### 优化 4：Landing 页盲盒启动

Thawly.ai 的 Blind-Box Brain Dump 对选择瘫痪很有效。在输入框下方增加按钮：

> 🎲 我选不出来，帮我随机选一个任务开始

点击后从预设的常见拖延任务中随机抽取（写周报、回邮件、整理桌面等）。

## 三、商业模式与免费体验路径

### 3.1 核心洞察

完美主义者的付费阻力不在价格，而在"注册/订阅/决策"本身的**启动成本**。

### 3.2 推荐模式：先体验，后注册，再付费

```
第一次打开 → 直接输入任务 → 完整协议体验 → 导出 Markdown
                    ↓
        弹出："登录可保存这份产出和历史记录"
                    ↓
        用户选择：匿名导出（免费）/ 一键登录保存
                    ↓
        第二次使用 → 提示：本月还剩 2 次免费协议
                    ↓
        第三次后 → 登录用户无限次，未登录用户引导注册
```

### 3.3 设计理由

| 设计决策 | 理由 |
|---------|------|
| **首次零注册** | 完美主义者可能在"想个用户名"上卡住 20 分钟 |
| **先给价值再要注册** | 用户已经拿到了 Markdown，感受到了"我真的做出了东西" |
| **次数限制而非功能限制** | 免费版功能完整，只是次数有限。完美主义者讨厌"残缺体验" |
| **导出优先于保存** | 本地文件是用户的，比"存在我们服务器上"更有掌控感 |

### 3.4 定价建议

| 层级 | 价格 | 内容 |
|------|------|------|
| **免费** | ¥0 | 3 次/月，全部功能，不保存历史 |
| **Pro** | ¥19/月 或 ¥99/年 | 无限次 + 历史记录 + 附件解析 + 自定义模板 |
| **终身** | ¥149 一次性 | 买断制，适合害怕订阅焦虑的完美主义者 |

### 3.5 关于终身制的特别提醒

完美主义者对"持续付费"有天然的抵触——"如果我这月没用就亏了"会制造新的焦虑。终身买断消除了这种不确定性。

营销卖点：

> "一次性解锁，再也不用为'这个月用了几次'而焦虑。"

## 四、关键结论

1. **Thawly.ai 是最接近的直接竞品**，但其 ADHD 定位与破冰协议的完美主义定位存在用户群体差异。
2. **破冰协议的"契约式"交互已构成差异化壁垒**——不是陪伴，是强制执行。
3. **步骤内微行动分解**是下一个最值得投入的功能优化点。
4. **商业模式必须消除"注册"这个启动成本**——先体验，后转化。
