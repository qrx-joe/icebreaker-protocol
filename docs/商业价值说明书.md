# 破冰协议 — 商业价值说明书

破冰协议解决的不是“我不想做”，而是“我太在乎，所以不敢开始”。Frost 多维完美主义量表相关研究长期指出，许多人存在过度在意错误、害怕负面评价、行动前反复准备的倾向。传统效率工具把问题理解成任务管理或专注力管理，但这类用户真正缺的是从心理安全区跨到可见产出的那一下。

## 核心价值

破冰协议是一套嵌入 Agent 的任务启动与成型协议。它通过启动契约、任务拆解、限时执行、上下文帮助、改进循环和产出评价，将用户从“准备阶段”推进到“手里已经有一个可以改的版本”。

它的价值不在于通用聊天，而在于强约束工作流：

- 把“做好”改写成“先做出可改对象”。
- 把大任务拆成 3-6 个可见产出块。
- 每步限定时间，降低无限准备的空间。
- 用户卡住时，`[Protocol]` 不提供鸡汤，而是直接给可复制、可修改的内容。
- 完成后只允许每轮改一处，避免“优化”继续伪装成拖延。
- 用产出质量评价器给用户一个诚实出口：到底能不能发布、投递或展示。

## 当前产品形态

| 形态 | 价值 |
|---|---|
| Agent Skill | 低成本分发，直接嵌入 Claude Code / Codex 等工作流 |
| Web demo | 展示完整流程：契约、路线图、计时、附件、语音、改进、评价 |
| CLI 工具 | `timer.py` 和 `review.py` 支持开发者在本地工作流中使用 |
| Vercel demo API | 便于轻量部署和公开演示 |

## 目标用户

- 完美主义者：不缺标准，缺可修改的第一版。
- 高敏感知识工作者：害怕暴露半成品，因此长期不交付。
- 创作者：选题、开头、初稿阶段最容易陷入空转。
- 求职者：简历、项目文档、投递材料反复想改但迟迟不发。
- 独立开发者：想做项目，但在技术选型、架构、README、发布前反复打转。

## 商业化方向

1. **免费基础协议**：以 Skill 和 Web demo 获客，让用户快速体验“我真的做出来了”。
2. **垂直模板包**：求职、创作、编程、产品方案、社交破冰等场景化拆解模板。
3. **高级评价与复盘**：基于历史产出形成个人启动画像、质量趋势和下一步建议。
4. **团队版**：用于黑客松、课程作业、内部创新项目，帮助成员从想法推进到可展示原型。

## 护城河

通用 prompt 可以模仿语气，但不容易复制完整闭环。破冰协议沉淀的是一套执行结构：什么时候逼用户开始，什么时候降低粒度，什么时候允许改，什么时候阻止继续改。这个结构比单句提示词更有复用价值。

一句话定位：

> 破冰协议不是帮你管理任务，而是逼你交出第一个能改的版本。
