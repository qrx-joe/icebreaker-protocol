# 破冰协议 · 战略定位与竞品对标分析

> 日期：2026-05-25
> 来源：基于 Thawly.ai 等新兴竞品的深度对标分析

---

## 一、差异化定位声明

### 一句话版本

> **Thawly.ai 是陪你散步的拐杖，破冰协议是逼你交稿的契约。**

### 对比矩阵

| 维度 | Thawly.ai | 破冰协议 |
|---|---|---|
| **核心假设** | 你动不了，需要外部推力 | 你怕做不好，需要心理许可 |
| **目标用户** | ADHD / 任务瘫痪 / 执行功能障碍 | 完美主义者 / 高思考低行动 |
| **交互模式** | 陪伴式（Continuous Execution） | 契约式（启动契约 + 限时交付） |
| **时间粒度** | 2 分钟微行动 | 15 分钟步骤（含三阶段计时） |
| **交付物** | 无明确产出，重在"做了" | 可导出的 Markdown 雏形 |
| **迭代哲学** | 持续陪伴，不离开 | 只改一处，防止完美主义无限循环 |
| **情绪干预** | Coach Mode 引导提问 | "乱写模式"强制降低标准 |

### 为什么这个差异很重要

Thawly.ai 的用户（ADHD）需要的是**外部结构**——他们内在缺乏组织感。破冰协议的用户（完美主义者）内在结构过剩（永远在脑子里规划），缺的是**对外交付的许可**。

你不是要"陪"他们，是要**逼**他们跨过心里那道线。

### 定位声明（用于对外传播）

> 市面上教你"如何规划""如何坚持"的工具已经够多了。完美主义者不缺规划——他们缺的是从"想"到"做"的那一瞬间的操作指令。破冰协议不管理任务、不切割时间、不提供激励。它只做一件事：**把启动成本降到零，并逼你交出一个可改的雏形。**

### 2.2 可借鉴 Thawly.ai 的优化方向

### 2.2 产品优化方向（按 ROI 排序）

#### 优化 1：步骤内微行动分解（最高优先级）

**问题**：每步 15 分钟对重度完美主义者还是太长。盯着空白文本区 15 分钟会重新触发启动恐惧。

**方案**：在 `goToStep()` 开始时，AI 再把这一步拆成 3-5 个**微勾选项**：

```
步骤：写博客大纲（15分钟）
  ☐ 先写第一个小标题（不管好坏）
  ☐ 再写第二个
  ☐ 填一个具体例子
  ☐ 加个结尾句
```

每勾选一个，局部进度条前进一格。用户不是"填满 15 分钟"，而是"勾选 4 个小框"。

**实现思路**：
- 后端：拆解 prompt 新增 `micro_actions` 字段，每步返回 3-5 个微行动
- 前端：`renderStepInstruction()` 中渲染 checkbox 列表，勾选状态存入 `stepOutputs` 的元数据
- 视觉：在现有进度条下方增加微进度条（4 格），完成全部后高亮"可以提交了"

**代码位置**：`demo/src/steps.js:13-35`（渲染指令区域）

---

#### 优化 2：Landing 页盲盒启动

**问题**：用户连"输入一个任务"都卡住——选择本身就是启动成本。

**方案**：在输入框下方增加 🎲 按钮：

> 🎲 我选不出来，帮我随机选一个

点击后从预设的常见拖延任务中随机抽取并自动填入输入框。

**预设任务池**：
- 写本周周报 / 回复那封拖了 3 天的邮件
- 整理桌面 / 备份手机照片
- 写一份简历 / 准备一个 5 分钟自我介绍
- 读完那本看了 20 页就放弃的书
- 给那个一直想说谢谢的人发消息

**实现思路**：前端纯静态数组 + `Math.random()`，零后端依赖。

**代码位置**：`demo/src/landing.js`

---

#### 优化 3：步骤间 AI 过渡语

**问题**：完成一步后直接进下一步，缺少"有人在你身边"的连续感。用户可能产生"我在原地打转"的焦虑。

**方案**：在步骤切换时（`goToStep()`）插入 AI 总结/鼓励语，显示在 `stepWarning` 区域：

```
[Protocol]: 第 1 步完成。你现在已经有了核心观点——比 90% 的人强了。
接下来我们把它变成大纲，不需要想得太复杂。
```

**实现思路**：
- 前端在进入步骤时，基于前序产出自动拼接一句过渡语（无需后端请求）
- 规则模板：
  - 第 1 步完成："第 1 步完成。你已经迈出了最难的一步。"
  - 中间步骤："第 N 步完成。[前一步产出的关键词] 已经就位，接下来 [当前步骤目标]。"
  - 最后一步："最后一步了。把已有的东西拼起来，不需要新增内容。"

**代码位置**：`demo/src/steps.js:47-96`（`goToStep()` 函数）

---

#### 优化 4：自动过渡，减少"点击下一步"的决策点

**问题**：用户写了足够多的内容，但还要主动点"做完了"——这个点击本身就是决策成本。

**方案**：在 `finishStep()` 前增加**智能检测**，当满足条件时主动提议：

```javascript
// 触发条件（满足任一）：
// 1. 已写超过 150 字，且计时器剩余时间 > 30%
// 2. 已写超过 50 字，且计时器已超时
// 3. 微行动分解模式下，所有 checkbox 已勾选

// 行为：在 stepWarning 区域显示内联确认
// [Protocol]: 看起来你已经完成了。按 Enter 进入下一步，或继续编辑。
```

**实现思路**：在 `steps.js` 的 textarea input 事件中增加检测逻辑，满足条件时显示轻量提示，用户按 Enter 即可确认，不需要鼠标移动。

**代码位置**：`demo/src/steps.js:37-44`（`updateStepSubmitState()` 函数）

---

#### 优化 5：奖励配对机制（Research-Backed）

**问题**：Dawdle AI 的研究表明，"任务拆分 + 即时奖励"比单纯拆分更有效。破冰协议目前只有"倒计时压力"，缺少"完成后的正向反馈"。

**方案**：每步完成后给一个**即时的、微小的正向信号**：

| 完成时机 | 反馈形式 |
|---------|---------|
| 第 1 步完成 | 进度条闪烁一次，文案："第 1 块产出已归档。" |
| 中间步骤完成 | 显示实际耗时（"用时 4 分 32 秒，比预期快"） |
| 最后一步完成 | 破冰战报完整展示，+ 一个随机成就文案 |

**成就文案池**（随机抽取）：
- "你从一个想法走到了一个雏形。这比 90% 的人强了。"
- "完美主义者最难的不是做好，而是做完。你已经做完了。"
- "这份初稿的价值不在于它多完美，而在于它存在。"

**实现思路**：前端纯静态，不需要后端。在 `archiveStep()` 完成后触发。

**代码位置**：`demo/src/steps.js:186-222`（`archiveStep()` 函数）

## 三、商业模式与免费体验路径

### 3.1 核心洞察

完美主义者的付费阻力不在价格，而在"注册/订阅/决策"本身的**启动成本**。

### 3.2 推荐模式：先体验，后注册，再付费

```
第一次打开 → 直接输入任务 → 完整协议体验 → 导出 Markdown
                    ↓
        弹出："登录可保存这份产出和历史记录"
                    ↓
        用户选择：匿名导出（免费）/ 一键登录保存
                    ↓
        第二次使用 → 提示：本月还剩 2 次免费协议
                    ↓
        第三次后 → 登录用户无限次，未登录用户引导注册
```

### 3.3 设计理由

| 设计决策 | 理由 |
|---------|------|
| **首次零注册** | 完美主义者可能在"想个用户名"上卡住 20 分钟 |
| **先给价值再要注册** | 用户已经拿到了 Markdown，感受到了"我真的做出了东西" |
| **次数限制而非功能限制** | 免费版功能完整，只是次数有限。完美主义者讨厌"残缺体验" |
| **导出优先于保存** | 本地文件是用户的，比"存在我们服务器上"更有掌控感 |

### 3.4 定价建议

| 层级 | 价格 | 内容 |
|------|------|------|
| **免费** | ¥0 | 3 次/月，全部功能，不保存历史 |
| **Pro** | ¥19/月 或 ¥99/年 | 无限次 + 历史记录 + 附件解析 + 自定义模板 |
| **终身** | ¥149 一次性 | 买断制，适合害怕订阅焦虑的完美主义者 |

### 3.5 关于终身制的特别提醒

完美主义者对"持续付费"有天然的抵触——"如果我这月没用就亏了"会制造新的焦虑。终身买断消除了这种不确定性。

营销卖点：

> "一次性解锁，再也不用为'这个月用了几次'而焦虑。"

## 四、产品优化优先级总览

| 优先级 | 优化项 | 预计工作量 | 预期收益 |
|--------|--------|-----------|---------|
| P0 🔴 | 步骤内微行动分解 | 2-3 小时 | **最高**。把"填满 15 分钟"变成"勾选 4 个框"，直接降低启动阻力 |
| P1 🟡 | Landing 页盲盒启动 | 30 分钟 | 快速复刻 Thawly.ai 最有效的功能，解决"连输入都卡住"的场景 |
| P1 🟡 | 步骤间 AI 过渡语 | 1 小时 | 增强连续感，减少"原地打转"焦虑 |
| P2 🟢 | 自动过渡（智能检测） | 1 小时 | 减少"点击下一步"的决策成本 |
| P2 🟢 | 奖励配对机制 | 2 小时 | Dawdle AI 研究验证，"拆分+奖励"比单纯拆分更有效 |

## 五、关键结论

1. **Thawly.ai 是最接近的直接竞品**，但其 ADHD 定位与破冰协议的完美主义定位存在用户群体差异。
2. **破冰协议的"契约式"交互已构成差异化壁垒**——不是陪伴，是强制执行。
3. **步骤内微行动分解**是下一个最值得投入的功能优化点（ROI 最高）。
4. **商业模式必须消除"注册"这个启动成本**——先体验，后转化。
5. **Dawdle AI 的研究发现值得借鉴**：任务拆分 + 即时奖励 > 单纯拆分。当前破冰协议只有"压力"（倒计时），缺少"奖励"（正向反馈）。
