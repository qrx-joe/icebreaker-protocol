# 破冰协议 · 项目建议与踩坑记录

> 版本：v0.1 | 创建日期：2026-06-01
> 本文档记录项目迭代中积累的**可复用原则**和**已踩过的坑**。

---

## 一、架构原则（先记住这 3 条）

### 1.1 任务复杂度 → 增加步骤数量，不增加单步时长
- 复杂任务拆成更多步骤，每步仍保持 1-15 分钟
- 原因：完美主义者在长步骤中会重新触发焦虑

### 1.2 空白是唯一失败；粗糙不是失败
- 协议不评价产出质量，只约束"不能留空白"
- 评价器只在**完成后**使用，不审判每一步

### 1.3 协议不评价用户，只约束动作
- `[Protocol]` 去人格化，不安慰、不共情
- 用户不能跟"协议"讨价还价

## 二、已踩过的坑（别重复）

| 坑 | 后果 | 解决方案 | 记录日期 |
|---|---|---|---|
| 前端模块迁移后未跑构建 | `npm run build` 报错，生产环境无法部署 | 每次重构后强制跑一遍构建 | 2026-05-30 |
| 本地后端与 Vercel serverless 逻辑重复 | 同一规则改两遍，容易遗漏 | 短期内接受，长期提取共享模块 | 2026-05-30 |
| AI 评价 Prompt 无版本管理 | 换模型后评价结果漂移，无法追溯 | Prompt 提取到独立文件，加 `prompt_version` 字段 | 2026-06-01 |
| Service Worker 缓存死锁 | 用户浏览器加载旧版 CSS/JS，新功能不生效 | `purgeStaleSW` + 构建时版本戳 | 2026-06-01 |

## 三、技术决策速查

| 决策 | 选择 | 理由 |
|------|------|------|
| 前端框架 | 纯 JS + Vite | 完美主义者会在框架选型上卡住，用最少依赖降低决策成本 |
| 后端 | FastAPI（本地）+ Vercel Serverless（线上） | 本地开发简单，线上零运维 |
| 状态存储 | localStorage | 先不给用户"注册"这个启动成本 |
| AI 模型 | GPT-4o-mini（默认）| 成本可控，响应快，评价任务不需要最强模型 |

---

## 四、什么时候该加功能，什么时候不该

**该加：**
- 当前闭环已经跑通，且用户反馈明确指向某痛点
- 新功能不破坏现有流程，可独立开关

**不该加：**
- 构建还没跑通就想加 UI 动效
- "竞品有所以我们也应该有"
- 用户没提，你自己觉得"很酷"
